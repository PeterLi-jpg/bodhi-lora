# Inference env (.venv-infer): vLLM serving for the probe, traces, filter, eval,
# grade and bench stages (bodhi_lora/pipeline/). It is separate from the training
# env of pyproject.toml because vLLM 0.9.2 cannot import with transformers 4.57.6. The runner starts them with
# python.infer of configs/project.yaml (default .venv-infer/bin/python).
#
# vllm: the submitted eval image asked for vllm>=0.6.5,<0.10
# (legacy/modal_eval.py:73) and the rebuttal requirements for >=0.9.0,<0.10.
# pip takes the newest version in range. On PyPI that was 0.9.2 (uploaded
# 2025-07-08; 0.10.0 followed on 2025-07-25) at both build dates (May and July
# 2026), so both ranges resolved to 0.9.2. No pip freeze from either run is in
# the repo to confirm it.
vllm==0.9.2
# vllm 0.9.2 requires torch==2.7.0 (its PyPI metadata). The train extra of
# pyproject.toml pins the same torch.
torch==2.7.0
# vllm 0.9.2 requires transformers>=4.51.1. Its ovis config registers "aimv2"
# without exist_ok, and transformers 4.54 and later ship their own aimv2, so
# `vllm serve` fails at import with transformers>=4.54. The exact version in
# the posted .venv-infer was not recorded.
transformers>=4.51.1,<4.54
bodhi-llm[all]==0.1.4
# bitsandbytes serves a 4-bit base (eval.base_precision: train on a QLoRA cell). The vLLM 0.9.2
# bitsandbytes docs ask for >=0.46.1.
bitsandbytes>=0.46.1,<0.48; sys_platform == "linux"
datasets>=2.18.0,<4.0.0
huggingface-hub
numpy>=1.24,<3.0
pyyaml>=6.0,<7.0
# The registry schema (bodhi_lora/registry/schema.py). vLLM 0.9.2 needs pydantic>=2.10,
# so both envs share the floor.
pydantic>=2.10,<3
tqdm>=4.65
# The probe stage computes its Fisher test with scipy (bodhi_lora/pipeline/probe.py).
scipy>=1.11,<2.0
